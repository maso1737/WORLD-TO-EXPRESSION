# PLAN — 解説スクロール LP（SCROLL EXPLAINER）

2026-11-03 起草。**SP-02 `SCROLL_BEATS_LP.html`・SP-03 `SCROLL_CONSONANCE_LP.html` 実装済み（11-03）**。音はユーザーの案で「スクロールで鳴る」に決定し、既定は **BOW**（スクロール中だけ鳴る）。ユーザーの発案：
「チャットでの解説はアプリを触れば分かるが、後で見返すと見失う。LP_motion-graphics の SCROLL_〇〇_LP の形式で
解説をスクロールで見せれば伝わるし、解説の面白さも残る。数式との関係も細かい表示でレイアウトに置きたい」。

## 方針

- **アプリ 1 本 ＝ 解説 LP 1 本を対にして作る**（sound-patterns の SP-xx、Emergence Engine の 01〜08）。今後の新作も「アプリ → 解説 LP」までを 1 セットにする。
- 形式は DESIGN MECHANICS と同じ**系統 A（sticky 章切替）**。骨格は `scroll-lp-grammar` スキル（正準 `LP_motion-graphics/SCROLL_MOTION_LP`）から複製する。
- **法則ファイルをアプリと共有する**（例：`sound-patterns/_law/sp02_law.js` をそのまま読む）。LP の絵・数値・音はアプリと同じ式から出るので、解説とアプリの数字が食い違わない。
- 置き場所は**教材の隣**：`sound-patterns/scroll/SCROLL_BEATS_LP.html` など。名前は `SCROLL_〇〇_LP` の型に揃える。
  WTE のリポジトリに入るので GitHub Pages で公開でき、法則ファイルを相対パスで読める（LP_motion-graphics に置くと別フォルダからの参照になり、公開もできない）。
- 見た目はアプリと同じ NATURAL 型（黒＋黄・方眼・HUD）。DESIGN MECHANICS 系の見た目とは混ぜない。

## 1 本の章立て（型）

| 章 | 中身 |
|---|---|
| 0 問い | アプリの最初の問いを 1 行で（例：近い 2 音はなぜ揺れる？） |
| 1〜n 仕組み | スクロールで 1 つずつ変数を動かす。絵はアプリと同じ描画を、スクロール位置 P の関数として動かす |
| 境界 | 状態が切り替わる所（SP-02 なら ONE→BEAT→ROUGH→TWO）を、スクロールでまたがせる |
| 種明かし | 「なぜそうなるか」の芯（SP-02 なら和を積に直す式） |
| 出口 | アプリへのリンク（その章の状態を URL で渡して開く）と、次の教材へのリンク |

## 数式の小窓（FORMULA RAIL）

- 画面の端に細い等幅の帯を置き、**いま絵で動いている項だけを黄色で光らせる**（例：Δf が動く章では `2cos(πΔf t)` の Δf が光る）。
- 実数値も小さく並べる（`Δf = 8.0 Hz → くびれ 8 回/秒`）。式の文字と画面の値が 1 対 1 で結びつくようにする。
- 読まなくても絵で分かり、読むと式と結びつく、という 2 段の読み方にする。

## 音

- 音は最初のクリックで有効にし、あとは**スクロールに合わせて鳴る**（既定 BOW＝スクロールの速さで鳴る弓／♪ ON＝鳴りっぱなし）。11-03 ユーザーの案で変更・BOW を既定に。

## 解説の掘り起こし

Emergence Engine のチャットでの解説は、セッションの記録に残っている。LP を作る前に、該当セッションから「なぜこう動くか」の説明を拾い、
`Emergence Engine/90_Log/` か各 LP の CLAUDE.md に箇条書きで残してから構成する（拾った解説が LP の台本になる）。

## 検証

- アプリと同じく `window.__SP` 相当の検証フックを持たせ、スクロール位置 P を手で動かして各章の絵・数値を確かめる。
- 動作チェック表（ユーザー共通ルール）を付ける。スクロール連動も「パラメータ」として扱う。

## 1. 共通規約（全ページ・全実装で厳守）

### 1-1. 品質バー（この5つを満たせば合格）
1. **触った瞬間に因果が見える** — スライダー/ドラッグの操作量と画面変化が1:1で対応する
2. **発見に報酬がある** — 「見えた！」の瞬間（閾値通過・スナップ・反転）に一拍の演出（ライム一閃、REVEALED表示など）
3. **証明部品がある** — 「絵は変わっていない／物理的には等しい」をその場で検証できるオーバーレイ
4. **直接操作 > スライダー** — ステージ上のドラッグ等で直接触れるならそちらを主、スライダーは併設
5. **どの状態で止めても絵になる** — 破綻フレームもデザインとして成立させる

### 1-2. 変更禁止・維持事項
- **CSS デザインシステムは変更しない**（`:root` 変数、topbar/side/bottombar 構造、フォント）。ステージ内の追加要素は既存トーン（ink #0a0a0a / lime #c8ff1a / mute）に従う
- 既存の共通部品を**必ず維持**: COPY/PASTE ボタンと JSON スキーマ（キー追加は可・削除不可）、ショートカットモーダル、`R`=Reset、`?`=一覧、`ESC`=index、verdict 表示
- 新しい操作を足したら**ショートカットモーダルと ed-hint に必ず追記**
- 1ファイル完結（外部ライブラリ・外部画像の追加禁止。SVGパスはJSに焼き込む）
- 二次テキストは読める明度に（`--mute` #999 より薄くしない）
- `prefers-reduced-motion` 配慮を維持

### 1-3. 実装の進め方
- ファイル全書き換え禁止。`<script>` と該当マークアップのみ**差分編集**
- 完了条件: preview で該当ページを開き、コンソールエラーなし・各操作の動作確認・スクリーンショット確認

## 3. ページ別仕様

### 3-1.【S】l3-08-anamorphosis.html — 本物の3D視点に作り直し

**現状**: `#art`（GEN·EXテキスト）に `scaleY` を掛けるだけ。床は clip-path の疑似台形で固定。
**問題**: 「絵は固定、視点だけが動く」というアナモルフォーシスの核心が画面から読めない。文字が伸縮して見えるだけ。

**修正内容**:
1. **CSS 3D 化**: `#scene` に `perspective: 900px` を与え、`#floor` に `transform: rotateX(calc(90deg − viewAngle))` を適用（JSで `floor.style.transform = \`rotateX(${90-state.viewAngle}deg)\``、`transform-origin: 50% 100%` 推奨・要調整）。clip-path の疑似台形は**削除**。床のグリッド背景はそのまま残す（遠近で潰れて奥行きを売る）
2. **アートは固定**: `#art` は床ローカルで `scaleY(K_STRETCH)`（定数、初期2.7）を一度だけ適用し、以後 transform を一切変更しない。`K_STRETCH` は「viewAngle = DESIGN_ANGLE(20°) のとき文字が正立して見える」よう実機で微調整
3. **ステージ直接ドラッグ**: `#main` 上の縦ドラッグで viewAngle を増減（下ドラッグ=視点が下がる）。スライダーは併設のまま双方向同期
4. **PLAN VIEW インセット**: ステージ左下に小窓（約 150×100px、ink枠1px、bg #fff）を常設。中身は「真上から見た床」＝ストレッチされたままのアートの縮小静止表示＋ラベル `PLAN VIEW · ARTWORK FIXED`。視点が変わってもこの窓は**絶対に変化しない**ことが証明
5. **スナップ演出**: viewAngle が DESIGN_ANGLE±3° に入った瞬間（外→内の遷移時のみ）、ステージ外周に lime の枠を 300ms フラッシュ。verdict は既存の REVEALED を維持
6. 既存の Viewpoint Marker（P キー・視線SVG）、legibility ゲージ、COPY/PASTE スキーマ（viewAngle, showViewpoint）は維持

**完成条件**: 90°で「縦長に間延びした смear」、20°付近で「正立した GEN·EX」が読める。ドラッグで連続的に遷移し、±3°進入時に一閃。PLAN VIEW は常に不変。

### 3-2.【S】✅実装済 2026-08-01 — 05-figure-ground.html

**現状**: ガウス合成の壺プロファイル。壺には見えるが**顔として読めない**。
**問題**: ルビンの壺の核心「同じ輪郭が顔⇔壺で反転する」が起きない。

#### 素材: 受領・検証済み（2026-08-01）

**`cognitive/svg/PROFILE_face-vase.js`** — これが正準アセット。**そのままファイル冒頭にインライン展開して使う**（外部読み込み不可の規約のため）。

- 出典: `cognitive/svg/tsubo_face.svg`（Illustrator, viewBox 1000×1000）。`tsubo_marge` / `face_marge` レイヤーは**23アンカーで頂点数一致**＝モーフ前提で作られている
- 検証済み: 両形状とも**完全左右対称**（中心 x=500.00）、**各走査線で単一区間**（x単調）。よって `[t, halfWidth]` テーブルに無損失で落とせる。321サンプル等間隔で書き出し済み
- 提供API:
  - `VASE_HW[] / FACE_HW[]` — 中央領域の半幅（プレート幅で正規化）
  - `hwOf(tbl, t)` — 線形補間
  - `contourHW(t, shapeCue, scale)` — **これだけ使えばよい**。`shapeCue` 0..100、`scale` は面積キュー

#### 検証で判明した最重要事項

**`shapeCue = 50`（VASE と FACE の 50% モーフ）が本物のルビン図**である。実測レンダリングで確認済み:

| shapeCue | 明暗 | 見え方 |
|---|---|---|
| 0 | 中央=暗 | 壺のみ読める |
| **50** | **中央=暗** | **壺として読める** |
| **50** | **両側=暗** | **顔として読める（眉・鼻・唇・顎が明瞭）** |
| 100 | 両側=暗 | 顔のみ読める |

→ **shapeCue=50 では輪郭を1ミリも変えずに、明暗を入れ替えるだけで壺⇔顔が反転する。** これがこのページの主役体験。
補足: 顔の鼻先どうしは shapeCue=100 でも接触しない（最小半幅 0.0317＝プレート幅の6.3%）。壺の首が常に残るので破綻しない。

#### 修正内容

1. `profileW(t)` を廃し、`contourHW(t, state.shapeCue, areaScale)` に差し替え。`buildVase` / `fillVase` / `clipFaceRegion` の構造はそのまま流用（点数が 321 に増えるだけ）
2. **Control 節を2スライダー構成に**:
   - `Shape Cue <span>輪郭の形（壺寄り⇔顔寄り）</span>` — 0..100、**初期値 50**。両端ラベルは `← VASE 壺` / `顔 FACE →`、中央に両義マーカー
   - `Area Bias` は現行のまま残す（`areaScale = 0.7 + areaBias/100 * 0.6` 相当で `contourHW` の第3引数へ。0.70〜1.30 の範囲は実測で全域破綻しないことを確認済み）
3. **TONE トグル追加**（Control 節、キー `I`）: `中央=暗` ⇔ `両側=暗` を切り替え。**shapeCue=50 のときこれを押すと知覚が反転する**のが本ページのハイライトなので、押した瞬間に verdict を `FLIPPED — 輪郭は不変、明暗だけが変わった` と 1.5秒表示する
4. **FLIP NUDGE ボタン追加**（キー `N`）: 現在「地」側の領域を 300ms だけ lime 0.25α でフラッシュし、反転を誘導。見えない人への救済
5. verdict / getVerd は shapeCue 基準に組み替え: `<20` = VASE DOMINANT / `20..80` = AMBIGUOUS（edge 強調）/ `>80` = FACE DOMINANT
6. Read 原理の本文を差し替え（現行は面積規則の説明）: **「同じ輪郭でも、どちらの側が輪郭を所有するかで図が決まる。形の手がかり（shapeCue）と明暗（tone）がその所有権を奪い合う」**
7. COPY/PASTE スキーマに `shapeCue:number` と `tone:'mid'|'sides'` を追加（`areaBias` `seenAs` `showGhost` は維持）

**完成条件**: shapeCue=50 で TONE を切り替えると壺⇔顔が反転して見える。顔側で眉・鼻・唇・顎が一目でわかる。両端では一方の解釈しか成立しない。

> **調整（2026-08-01、ユーザー確認後）**:
> - `showGhost` の初期値を **false** に変更（Show Cue は初期OFF。マークアップ側 `#tg-ghost` の初期 `on` クラスも外した）。答えを先に見せず、自分で反転を探す体験を優先。
> - 実機で比較した結果、`shapeCue` の両義点として **50 より 95 のほうが壺・顔ともに明瞭**（壺の首がくびれ、顔の凹凸も強く出る）と判断 → **l3-07-rubin の固定輪郭にこの知見を反映**（05 側の `Shape Cue` スライダー自体は 0..100 可動のまま、初期値50も変更なし）。

### 3-4.【A】06-common-fate.html — 「動きだけが群を作る」を体感させる

**現状**: coherent ドットが常時 lime で塗られる（showGroup 初期 ON）。
**問題**: 色分けが答えを先に見せてしまい、「同じ動きだけで群が浮かび上がる」発見体験を潰している。

**修正内容**:
1. `DEFAULTS.showGroup` を **false** に変更（proof は「見えた後の答え合わせ」に）
2. **FREEZE トグル追加**（サイドパネル Control 節、キー `SPACE`）: 全ドットの移動を一時停止。停止すると群が完全に消えて均一なランダム点群に戻る → 再生すると群が再び立ち上がる。この ON/OFF の落差が本テーマ最大の「得られた感」
3. FREEZE 中は verdict を `FROZEN — 動きが消えると群も消える` に
4. COPY/PASTE スキーマに `frozen:boolean` を追加（既存キーは維持）

**完成条件**: 初期状態で色の手がかりゼロのまま coherence を上げると群が「見えてくる」。SPACE で止めると消える。proof ON で答え合わせできる。

### 3-5.【A】07-symmetry.html — ミラードラッグで対称を「手で」感じる

**現状**: スライダーで左右輪郭の対称度をブレンド。眺めるだけで、対称の「連動する感じ」が伝わらない。

**修正内容**:
1. **ステージ直接ドラッグ**: 左輪郭の近く（ヒット判定: 輪郭から40px以内）を縦ドラッグすると、その付近の `baseProfile` を局所的に膨らませ/凹ませられる（ガウス窓で±10サンプル程度を加算）。**右輪郭は symmetry の値に応じて追従**する — symmetry=100 なら完全ミラーで即座に連動、下げるほど追従が弱まる（既存の `sym * mirror + (1-sym) * noise` ブレンドがそのまま効く）
2. ドラッグ編集はセッション内のみ（Reset で `generateProfiles()` に戻す）。編集中はカーソルを `ns-resize` に
3. 既存のスライダー・complexity・axis proof・verdict はすべて維持
4. ed-hint に「輪郭をドラッグで変形 — 対称度が高いほど反対側が連動する」を追記

**完成条件**: symmetry=100 で左をつまむと右が鏡写しに動く（気持ちいい）。symmetry を下げると連動が壊れていき、図の立ち上がりも弱まるのが分かる。

### 3-6.【A】l3-01 / l3-02 / l3-03 — NULL & MEASURE（自分の錯視量を測る）共通タスク

**現状**: 錯視を眺めて ruler で確認するだけ。受け身。
**狙い**: 心理物理学の調整法（nulling）。「同じに見えるまで自分で調整→実測とのズレ＝あなたの脳の錯視量」を数字で突きつける。

**修正内容**（3ページ共通パターン、各ページに個別実装）:
1. **MATCH モード追加**（サイドパネルに `Measure <em>計測</em>` 節を新設、キー `M` でトグル）

2. **JUDGE 時**: ruler/同心円オーバーレイを自動 ON にし、物理差を測定。`YOUR ILLUSION: +8.2%`（調整量＝錯視量）を verdict 位置に 3秒表示 ＋ Measure 節に LAST / BEST を記録表示
3. MATCH OFF で通常表示に戻る（調整値はリセット）
4. COPY/PASTE スキーマに `lastIllusionPct:number|null` を追加

**完成条件**: 錯視条件下で JUDGE すると 5〜15% 程度の錯視量が出て驚ける。錯視オフ状態（angle=0 等）で JUDGE するとほぼ 0% になる（自己検証が成立）。

### 3-8.【A】L2 全6ページ共通 — GAZE PARTICLE（視線粒子）

対象: l2-01-size-weight, l2-02-density, l2-03-contrast, l2-04-visual-flow, l2-05-balance, l2-06-negative-space。
**現状**: 重心 crosshair がテレポート的に動くだけで、「視線が引っ張られる」感覚が薄い。

**修正内容**（各ページ共通、`Proof` 節にトグル `Gaze Particle` を追加・初期ON・キー `E`）:
1. 中空円の粒子（半径6px、ink 枠 1.5px・lime 塗り、うっすら残像トレイル最大20点・α減衰）を1個表示
2. 物理: ばね追従で `weighted centroid`（各ページ既存の `C.wx, C.wy`）に引かれる。`acc = (target − pos) * 4.0 − vel * 3.0` を rAF で積分（時定数はこの比率を基準に微調整）。パラメータ変更のたびに目標が動き、粒子が「落ちていく」のが見える
3. l2-04 のみ: 目標へ直行ではなく**最寄りの矢印ベクトル場に沿って流される**（矢印の向きを速度に加算）— 「流れが視線を運ぶ」の直訳
4. rAF は粒子表示中のみ回す（既存ページは静的描画なので、粒子レイヤーだけ別 canvas か、既存 draw を rAF 内呼び出しに変更。負荷を上げすぎない）
5. COPY/PASTE スキーマに `showGaze:boolean` を追加

**完成条件**: スライダーを動かすと粒子がスッと新しい重心へ滑る。均一状態（off）では中央に静止。6ページで同じ手触り。

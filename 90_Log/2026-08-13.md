### 実装したもの（MATCH & MEASURE ＝心理物理学の調整法）

- **Measure 節を新設**（Proof の下・キー `M`）。ON にすると**下の軸（`<──>` 側＝長く見える方）だけ**が可動になり、上の軸は固定基準になる。
  - 調整は **ステージ左右ドラッグ**（主）＋ **←→ キー**（副・0.5%/押下）。範囲 **±20%**（0.80〜1.20）。
  - ドラッグはステージのどこを掴んでもよく、**中心より右なら右へ、左なら左へ**引くと伸びる（中心対称スケール）。`geo()` を切り出して draw とドラッグでジオメトリを共有。
  - **開始長は毎回ランダム（±12%）**。ここが設計の要で、初期値1.00固定だと「触らなければ物理的に等しい」が答えになってしまい、錯視オフ時の自己検証（完成条件）が成立しない。
- **JUDGE（ボタン／`ENTER`）**: 定規オーバーレイを自動 ON にし、`YOUR ILLUSION +8.2%` を verdict に3秒表示 ＋ 外周 lime 300ms フラッシュ。Measure 節に `LAST +8.2% · BEST +12.4% @55°` を記録（BEST＝**絶対値最大**の錯視量とその角度）。
- **判定前は答えを隠す**（これが無いと計測にならない）:
  - 定規トグルは MATCH 判定前だけ**無効化＋グレーアウト**（`P` も no-op）。ラベルに「MATCH 判定前は無効」を併記。
  - ボトムバー TRUE セルは判定前 `HIDDEN` → 判定後 `Δ −8.2%`。
  - ステージのキャプションも `FINS IN/OUT — 短く/長く見える` → `REFERENCE 基準（固定）` / `⟷ ADJUST 同じ長さに合わせる` に差し替え（方向のヒントを消す）。角度0°でも MATCH 中はこの2行を出す（＝自己検証時に操作が読める）。
- **証明の見せ方**: 判定後は上軸の端に垂直ガイド、両軸に定規、さらに**下軸の不足分を lime バー＋インクの目盛キャップ**で明示。「あなたが物理的にこれだけ縮めた」が絵で分かる。
- **試行の作法**: JUDGE 後のボタンは `⟲ RETRY` に変化（＝新しいランダム開始長で次の試行）。**角度を変えると判定済み試行は自動で無効化**され新試行になる（錯視条件が変われば測り直しが筋）。MATCH OFF で調整値は 1.00 に戻る。LAST/BEST は残る、`R` で全消去。
- COPY/PASTE スキーマに **`lastIllusionPct:number|null`** を追加（既存キーは維持）。ショートカットモーダルに `M` / `←→` / `ENTER` / `DRAG` の4行を追記、Measure 節に ed-hint。
- 符号の規約: **下軸を縮めて一致 = 正**（`illusionPct = −(matchScale−1)×100`）。逆方向は負で表示し、|値|<2% は「ほぼゼロ — この条件では錯視はほとんど働いていない」と文言を切り替える。

### 符号の一般化 — `ILL_SIGN`

l3-01 は**見かけが長い方**を可動にしたので「縮めて一致＝正」だったが、02/03 は仕様どおり
**見かけが小さい方**（ponzo=下バー NEAR ／ ebbinghaus=右の中心円）が可動なので「伸ばして／大きくして一致＝正」になる。
そこで各ページ冒頭に定数を置いた:

| ページ | 可動側 | 見かけ | `ILL_SIGN` | 期待される操作 |
|---|---|---|---|---|
| l3-01 muller-lyer | 下の軸 `<──>` | 長く見える | **−1** | 縮めて一致 |
| l3-02 ponzo | 下のバー NEAR | 短く見える | **+1** | 伸ばして一致 |
| l3-03 ebbinghaus | 右の中心円 | 小さく見える | **+1** | 大きくして一致 |

`illusionPct = ILL_SIGN × (matchScale − 1) × 100`。**表示は3ページとも「錯視が期待どおり効いた＝正」**に揃う。
判定文も向きに合わせて出し分ける（「縮めて」「伸ばして」「大きくして」）。

なお ponzo で可動側を上バー（FAR）にしなかったのは仕様どおりというだけでなく、
**上バーは収束線に近く、±20% すると線路の幅に触れてしまう**（＝バーとレールの距離自体が Ponzo の手がかりなので、
測定中に文脈が変わる交絡になる）。下バーは全域でレールに触れないことを幾何で確認済み。

### l3-03 だけの差分

- **可動量は「長さ」ではなく「半径」**。ドラッグは**円のフチを任意の方向に引く**（極座標の距離差を使うので上下左右どこからでも掴める）。ハンドルは lime の破線リング＋N/E/S/W のタグ。

  素直に 1:1 で引くと **±20% の全可動域が 7px のドラッグに収まってしまい**、狙って合わせられない。
  0.25 を掛けて**全可動域 ≈ ±29px**（l3-01/02 の ±30px とほぼ同じ手触り）に揃えた。実測で確認。

## 同セッション続き — L2 全6ページに GAZE PARTICLE（§3-8）

`l2-01`〜`l2-06` に視線粒子を実装。**6ページとも `computeCentroids(cx,cy,span) → {gx,gy,wx,wy,pull}` と
`draw()` 内の `const C = ...` が完全に共通**だったので、共有ブロック1つをそのまま6ファイルへ複製できた。

### 設計

- **粒子**: 半径6px・lime塗り・ink枠1.5px、残像トレイル最大20点（α 0〜0.30 で減衰）。Proof 節にトグル `Gaze Particle`（初期ON・キー `E`）。
- **物理**: `acc = (target − pos) * K − vel * D` を rAF で積分。target は各ページの**重み付き重心** `C.wx, C.wy`。
- **`lastC` 方式**: `draw()` が毎回 `lastC = C` を置くだけで、rAF ループ側はページ固有の span 計算を一切知らずに済む。
  → 6ファイルで**共有ブロックが1文字も変わらない**（l2-04 の追加分だけがページ固有）。
- **`stepGaze(dt, tx, ty)` をループから分離**。Browser ペインは rAF が止まるので、**手で積分を回して検証できる**ようにするため
  （＝一時フックを仕込まずに済む。HANDOFF の「検証後にフックを除去」問題が起きない）。
- **自己アーム式ループ**: `draw()` の末尾で `armGaze()` を呼ぶだけ。どの操作ハンドラも粒子のことを知らなくてよく、
  **静止したら rAF は自分で止まる**（＝静的ページに常時 rAF を足さない）。
- `prefers-reduced-motion` 時は**ばねもトレイルも無効**にして目標位置に即座に置く（点は残るので情報は失わない）。

### §3-9 l2-05 — 天秤をステージ主役へ

サイドパネルの CSS 部品だった天秤を canvas でステージに描き、**左右の円をその皿に載せた**。

- **構成**: 支点三角＋接地線＋梁＋左右のハンガー＋トレイ。皿は梁が傾いても**水平を保って吊り下がる**。
- **傾き** `(mL − mR) × 18°`、指数イージング（τ=0.10s ≒ 元の `transition .18s` の手触り）で追従。
- **釣り合った瞬間に一拍**: 傾きが 0 に落ち着いた遷移で梁・皿・支点が **lime に 0.45秒フラッシュ**（エッジトリガ）。
- サイドの `Scale 天秤` 節は **`Mass 質量`** に置換（L/R MASS の数値だけ残す）。Proof トグル `Balance Scale` は**ステージ天秤の ON/OFF** に付け替え。
- **OFF は元の構図に戻る**（円が中央線上に並ぶ）。`mix` を 0↔1 でイージングしているので、トグルが A/B 比較として成立する。

#### 詰めた3点（いずれも最初の実装では破綻していた）

1. **円が天秤より大きすぎた。** `baseR = span*0.62` は梁の腕長 `0.52 span` より大きく、初回スクショでは
   **円が梁も支点も皿も飲み込んでいた**。天秤に載る時だけ `baseR` を `0.34 span` へ縮める（`mix` で補間するので
   OFF 時は元の比率のまま）。皿の幅も**各々の積荷に合わせて可変**にして、重い円が自分の皿を隠さないようにした。
2. **ハンガーを 0.15→0.07 span に短縮。** 皿を梁のすぐ下に吊ると、円は梁の**上**に乗る形になり、梁が隠れる範囲が最小になる。
3. **PULL が釣り合い時に 7% 残った。** 円が皿に乗って cy より下に来たのに、幾何中心を `cy` に固定していたため。
   → 幾何中心を**2要素の非加重平均**（他の L2 ページと同じ定義）に変更。実測で 0/13/22/42%（balance 100/70/50/0）と、
   釣り合いで 0% になることを確認。重心 `wy` は円の**加重平均 y** にしたので、重心マーカーと視線粒子が**重い側へ沈む**ようになった。

#### 共有ブロックへの拡張点追加

天秤のイージングのために **2本目の rAF ループを作ると draw() が毎フレーム2回走る**。そこで `gazeField` と同じ流儀で
`pageStep(dt)` / `pageSettled()` の拡張点を**共有ブロック側に追加**し、L2 6ファイルの同型を維持した（未定義の5ページでは素通り）。
併せて `gazeFrame` は「粒子が非表示でもページ側のイージングは進める」よう構造を変えた。

#### ⚠️ 踏んだバグ — `ACC` は L3 にしかない

`drawScale` の lime フラッシュで `ACC` を参照したところ、**L2 ページには `const ACC` が存在しなかった**
（L3 の8ページだけが持っている）。結果、**初めて釣り合った瞬間に ReferenceError が投げられ、rAF ループごと死んだ**
——「傾きが二度と動かない」という形で表面化した。l2-05 に `const ACC` を宣言して解決。
**他の L2 ページで lime 定数を使うときは同じ罠がある。**

### §3-10 l3-05 ベンハムのコマ — STROBE モード

**⚠️ 仕様 §3-10 の手順1「preview で目視して色が見えるか確認」は原理的に自動化できない。**
フェヒナー色は**観察者の網膜で生成される**ので、スクリーンショットのピクセルには存在しない（円盤は定義上ずっと白黒）。

| 最高 300rpm | 5.0 回転/秒 ＝ **12 フレーム/回転** ＝ **30°/フレーム** |

→ **円弧バンドは1つ45°セクタなので、最高速では1バンドを約1.5フレームで通過する。**
色の元になる細かい明暗リズムがほとんどサンプリングされない、という仕様書の懸念は**数値上は妥当**。
なお古典的なベンハムのコマは 5〜10 回転/秒 が有効域とされるが、このページは**上限が 5 回転/秒＝有効域の下端**、
既定の 160rpm は**その下**にある。`colorStrength()` も 130rpm で頭打ち・250rpm 超で減衰と、文献の傾向とは逆向き。
→ **これは知覚の話なので勝手に再チューニングせず、申し送りに残した。**

#### 実装（既定 OFF ＝ 連続回転の挙動は一切変えていない）

- Control 節に **`Strobe` トグル（キー `T`）＋ `Step Rate` スライダー（6〜18Hz）**。
- 円盤を **45°ずつ跳ばして**描画（1ステップ＝円弧バンド1つ分）。
- ⚠️ **ステップをフレーム数に整数分周で吸着**させた。60Hz で 12Hz 要求なら「5フレームに1回」。
  自由走行のタイマーにすると**フレーム間でジッタが出て、この モードが作ろうとしている明暗リズム自体が滲む**。
  起動時に rAF を24フレーム測ってリフレッシュレートを取得し、**実際の点滅数を下部バー SPIN に `12.0Hz · 1/5f` と明示**する
  （要求18Hz→実際19.96Hz のような吸着のズレを隠さない）。
- ⚠️ **STROBE 開始時に角度を 45°グリッドにスナップ。** 連続回転から引き継いだ半端な角度のままだと
  **1ステップが常にバンド境界をまたぎ**、リズムが滲む。実測で 45.0000°・24ステップ後もグリッド維持を確認。
- 連続回転中は Step Rate 行を、STROBE 中は Spin Rate をそれぞれ**グレーアウト**（効かないパラメータを悩ませない）。
- `colorStrength` / `getVerd` は `effRpm()`（STROBE 時は実効 45°/step から換算）を見るので、既存の帯域判定がそのまま生きる。
- dnote に**リフレッシュレート依存の但し書き**を追加（仕様 §3-10 項目3）。

#### ⚠️ 踏んだバグ — ボトムバーは5列グリッド

最初 `ACTUAL` を**新しい bb-cell として追加**したところ、`#bottombar` の `grid-template-columns` が5列のままで
**SHORTCUTS が2行目に折り返した**。そもそも共通規約で「bottombar 構造は変更しない」なので、
**SPIN セルの中に収める**形に変更（`SPIN STROBE 12.0Hz · 1/5f`）。高さ30pxの1行に戻ることを実測で確認。

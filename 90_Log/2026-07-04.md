## 追記 2026-08-01 — 横顔／壺SVG 受領・検証・アセット化

- ユーザーから `cognitive/svg/tsubo_face.svg`（+ `.ai`）を受領。`face` / `tsubo` / `face_marge` / `tsubo_marge` の4レイヤー。
- 解析結果:
  - `face_marge` / `tsubo_marge` は**ともに23アンカーで頂点数一致**＝モーフ前提で作られていた
  - 両形状とも**完全左右対称**（中心 x=500.00）・**各走査線で単一区間**（x単調）→ `[t, halfWidth]` テーブルに無損失変換できることを数値で確認
  - face と tsubo は「共有された1本のルビン輪郭」ではなく**別々の2つの silhouette**。そのまま片方だけ使っても双安定にならない
- **決定的な発見**: 両者の **50% モーフが本物のルビン図**。実測レンダリングで、輪郭を固定したまま**明暗を入れ替えるだけで壺⇔顔が反転**することを確認（顔側は眉・鼻・唇・顎が明瞭）。鼻先は最大モーフでも接触しない（最小半幅 6.3%）。
- 成果物: **`cognitive/svg/PROFILE_face-vase.js`**（321サンプル×2テーブル＋`contourHW(t, shapeCue, scale)`。7KB、インライン展開して使う）
- 仕様書 §3-2 / §3-3 / §4 / §5 を実測に基づいて全面改訂。05 は `Shape Cue` スライダー＋`TONE` トグル構成へ、l3-07 は輪郭を shapeCue=50 固定にして既存の陰影キューだけで誘導する設計に確定。

## 追記 2026-08-01（続き）— 05 / l3-07 実装完了

### 05-figure-ground
- `profileW()`（ガウス合成）を廃止し `contourHW(t, shapeCue, scale)` に差し替え
- Control を3つに: **Shape Cue**（0..100・初期50＝両義）／**Area Bias**（弱いキュー・`areaScale = 0.70..1.30`）／**Tone**（中央暗⇔両側暗）
- Tone 切替時に verdict を `FLIPPED — 輪郭は不変、明暗だけが変わった` で1.5秒上書き（このページの主役体験）
- **Flip Nudge**（キー N）: 現在「地」の側を 300ms ライムでフラッシュ
- verdict は2キューの合算 `cueScore = (shape-50)/50 + (area-50)/50*0.5`、|score|≤0.6 で AMBIGUOUS（既定 area で shape 20..80 が両義帯）
- キー再割当: ↑↓=Shape / ←→=Area / I=Tone / N=Nudge（モーダルも更新）。COPY/PASTE に `shapeCue` `tone` 追加
- プレートは `PLATE_RATIO 1.06` の固定比＋高さ基準スケール（`PROF_ASPECT`）で**輪郭が歪まない**

### l3-07-rubin
- 輪郭を **shapeCue=50 固定**（`BISTABLE_CUE`）にし、既存の `cueStrength`＝陰影・明度キューだけで解釈を誘導。`addVasePath` のシグネチャは維持
- **既存バグを2件発見・修正**（`git HEAD` と同一コード＝今回の差し替えとは無関係）:
  1. 壺側キューで、内側グラデーションの**後**に平坦な塗りを重ねてグラデーションを消していた → 描画順を入替
  2. 白→黒の1本グラデーションが Canvas の非乗算補間で灰色を経由し、影側が**明るく**なっていた → 0.5 に停止点を2つ置いて左右を独立
  - 修正前は `cueStrength 0/25/50` で画面がまったく同じ＝スライダー左半分が無反応だった

### 検証方法
ブラウザペインが非表示で screenshot が使えなかったため、**実キャンバスのピクセルを読んで数値照合**した（輪郭半幅の期待値との差1〜2px以内、ライム合成値の理論値一致、TONE/キー/リセット/記録の全経路）。

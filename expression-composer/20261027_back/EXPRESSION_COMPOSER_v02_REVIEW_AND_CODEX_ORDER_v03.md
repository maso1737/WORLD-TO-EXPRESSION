## 1. 変更しない価値（必ず保持）

1. **同一条件のA/B:** 同seed、同初期位置・速度、同stepで、ALIGN ON/OFFだけが違う。Φは平均進行方向の一致度であり、群れの「美しさ」「生命感」全体の点数ではない。
2. **データの実在性:** 600粒子・固定step・PRNG。ライブ画面の整数周期コピーは可。ただしポスターに架空点・見栄え用の追加点を混ぜない。
3. **採取と保存:** snapshotの各ID・位置・速度・seed・step・rule・hashを変更しない。編集は写像と表示選択のみ。PNG 1800×2400と全粒子入りJSONの往復再現。
4. **3つの構図哲学:** SILENCE=省略・余白 / CURRENT=速度・方向 / SIGNAL=一つの実粒子を焦点化。3枚は同一snapshot由来。
5. **v0.2で達成した使用条件:** ビルド不要・外部依存なし・ダブルクリックで起動可能、`window.__EC` APIと既存DOM ID、reduced-motion、既存のアクセシビリティ、過去の検証資料。

## 2. 観察に基づく評価

### 成立していること

- `1440x900-rule.png` はZOOMで粒子群を主役として見せ、元のv0.1よりダイナミック。
- `1440x900-compare.png` はONの整列とOFFの散逸が目視で区別できる。段階チップでPERCEPTIONを選びやすくなった。
- `contact-sheet.png` と `claude-review/v02/sheet_2026_900_A/B.png` で、同じA側／B側snapshotから3つの構図が成立している。特にB側は散在した群れが編集素材として活用されている。
- `1440x900-edit.png` はステージと編集パネルが整理され、参考画像のNOIR/PAPER/YELLOWの語彙を適切に抽出。

### まだ惜しいこと

- A/Bは **左右で独立した追跡カメラ**（`js/main.js renderStage`, `js/render.js followCamera`）。比較条件は正しいが、見ている位置も動くので、観客は「どこまでが法則の差か」を直感的に把握しにくい。
- WORLD→PAPERの中間フレームは、暗い矩形内の粒子が移動して終盤に紙になる。数学上は同IDで連続だが、鑑賞上は「箱が縮み、最後にポスターに切り替わった」に寄りやすい。**変換の意味が見える決定的な一瞬**が欲しい。
- SILENCE / CURRENT / SIGNAL は確かに違うが、情報設計はまだ共通テンプレート感が強い。CURRENTでは大文字と実粒子の重なりがseedによって偶然に左右される。SIGNALの黄色点は意味があるが、ほかの文字・点との視線構造をもっと整えられる。
- UIの操作ラベルに9〜11pxが多く、特にスマホのチップは7〜8px。スクリーンショットに表示上の破綻はないが、**読める・理解できる**の実機試験は別に必要。
- 1440×900では主要ステージが約720px高いため、状況によってステージ直下の次アクションが初期表示範囲外になる。45〜90秒の導線は自動テストのPASSだけでは保証できない。

## 3. v0.3で制作する3件（優先順）

### P1-01 / CAUSAL VIEW — 同じ視点から因果を見せる

**対象:** `js/main.js`, `js/render.js`, `index.html`, `styles.css`, README/docs/verification。

現行FOLLOWビューを残したまま、COMPAREだけに **VIEW: LOCK / FOLLOW** を用意する。推奨はCOMPARE入場時はLOCK。LOCKではA/Bの**同一カメラ座標・同一ズーム・同じ世界座標系**を使用する。双方が画面内に入りにくい場合は共通の構図だけを調整し、各群れを別々に中心寄せしない。FOLLOWでは既存の左右独立追跡を維持できる。ビューの変更でsim・step・Φ・snapshot hashは変えない。

表示は小さな一文でよい：`SAME INITIAL WORLD / ONLY ALIGN DIFFERS`。step 0では左右が視覚的に一致し、その後徐々に差が生まれることを観客が確認できるようにする。必要なら `REPLAY A/B FROM ZERO` を追加。ただし独立した大きなタイムラインは不要。

**受入:** ①step0のA/Bの世界座標・投影座標・粒子画像一致 ②step600で実粒子hashとΦが現行と一致 ③LOCK/FOLLOW切替でsimulation/snapshot不変 ④4画面幅でラベル・操作可能 ⑤比較を通らず採取する従来経路も保持。

### P1-02 / TRANSFORMATION — WORLD→PAPERを作品の山場へ

**対象:** `js/render.js renderFreeze`, `js/main.js take`, 画面文言と検証画像。

既存の **同一ID点の移動・周期コピーのフェード・紙への色反転** を絶対に壊さない。そのうえで、場面の意味が伝わる時間配分へブラッシュアップする。

推奨キーフレーム：

- **0–15%** 採取した瞬間を固定して見せる（「世界が止まった」ことを明示）。
- **15–70%** 世界の表示領域から紙面へ、粒子IDの連続性を追える速度で移送。大量の別粒子を発生させない。
- **70–88%** モーションに一瞬の抑制・静寂を設け、再解釈される予感を作る。
- **88–100%** 紙・墨の反転とタイポグラフィの成立を鋭く行う。最後は確実に静止。

時間比は初期案。**既存の1150msをむやみに長くしない**。必要なら短縮してもよい。reduced-motionは既存100ms程度で意味を損なわず終了。中間で点を背景と同色に消さない。

**受入:** screenshotまたはフレームストリップを0/15/35/60/80/90/100%で比較、実粒子600ID・座標写像を照合。開始のsource描画と最後のrenderComposition一致。PC/スマホ・reduced-motionで確認。見栄えのための別点群へのすり替えは禁止。

### P1-03 / ART-DIRECTED POSTER — 編集の意志がデザインに見える

**対象:** `js/composition.js FRAMES/compositionGeometry`, `js/render.js drawTypography/renderComposition`, `styles.css`, QA。

3プリセットの哲学は変えず、各々の造形ルールをもっと明確にする。架空粒子や疑似トレイルを追加しない。

- **SILENCE:** 小さな群れを残した余白は守る。その代わり、活字の密度・視線の起点・静かな不均衡で「狙って省略した」印象を強める。単純に巨大化しない。
- **CURRENT:** 実速度方向の線を主役に。群れがタイトルの真裏に入り込みすぎるseedで、文字を読みづらくしない。データの外接位置から **2〜3つの事前定義された組版案**を選び、字の重なりを狙った構図にする。点そのものは動かさない。
- **SIGNAL:** 選ばれた1つの実粒子を黄色で強調する方針を保つ。黄色を装飾として増やさず、注目点とタイポの関係を設計する。黄色点が文字の重要部に重なって見失われないようにする。

`drawTypography`はsnapshot由来の幾何と整合する描画位置を採ること。タイトル編集時は安全な文字折返し・縮小を維持。プレビューと1800×2400の出力は**同じ組版決定**であること。別環境でフォントが違う際はfallbackを記録し、必要なら配布許諾のあるWebフォントだけを同梱する。

**受入:** `seed 7 / 42 / 2026 × A/B × step400 / 600 / 900` を重点サンプルとし、SILENCE/CURRENT/SIGNALのコンタクトシートを生成。最も見づらい例も報告。少なくとも3つのプリセットで、背景色以外に構図と視線誘導が区別できる。密度・方向・点数のデータを偽装しない。

## 4. 小さなUI修正（上の3件に付随してよい）

- 主要CTA（COMPARE / TAKE A/B / FINISH / EXPORT）が、現在段階で発見しやすい位置にあるかを実視認で確認する。ステージを削って「一画面に詰める」ことはしない。必要ならステージ下部のCTAと視線誘導を改良。
- 説明文・操作ラベルの階層を整理。デスクトップ操作説明11〜12px以上、モバイル重要ラベルは10〜12px以上を目安に**実機倍率で読めること**を優先。作品内の極小メタデータは装飾として許容しても、操作説明を極小にしない。
- 3プリセットの切替がKEEP/SPACE/TRACE/FOCUS量をリセットする現在の仕様は保持してよいが、操作直近に簡潔に明示（現状は比較ストリップ末尾の小さい注記）。「編集中の値が消えた」と誤認しない設計にする。
- 初回ユーザー5人程度に、説明なしで「③比較を観る→A/B採取→3構図→PNGとJSON」まで到達できるか観察。人数・時間・迷い箇所を記録。45〜90秒は**目標**であって現時点の実測事実ではない。

## 5. 実装上のハードルール

- 編集は `expression-composer/` 内だけ。既存 `cognitive/`、`Emergence Engine/`、`scroll-experience/`、ルート `index.html` を今回変更しない。変更前バックアップを保存。
- `images/` 原画、マスタープラン、`verification/claude-review/`、既存のQA記録は原則上書きしない。新しい検証結果は`verification/v03/`などに別保存。
- `window.__EC` の既存メソッド名、既存DOM ID、JSON `schemaVersion:1` の復元互換性を維持。必要なUI状態が増える場合も、作品の再現JSONと表示専用のカメラ設定を明確に分離する。
- 既存作品の点・粒子IDの捏造なし。シミュレーション規則、600粒子固定、独立同期更新は無変更を基本とする。
- npm/CDN/外部API/新規ライブラリなし。`file://`直開き維持。commit/push/公開は行わない。
- 前回の実測ベースライン（sample seed42 step600 A のsnapshot hash `5828ce7f` on Chromeの提出環境）を回帰検出に使う。別JSエンジン間のhash完全一致は要求しない。

# 0. Codexへの実行指示（最初に読む）

あなたは **クリエイティブ・テクノロジスト／モーションデザイナー／実装エンジニア／QA担当** です。**計画を出すだけで終わらず、下記のフェーズに従って動くプロトタイプを実装し、ブラウザで検証し、確認画像とレポートを残してください。**

今回の目的は「実験の数を増やす」ことではありません。すでにある **生成の法則（RULE）→ 見え方（PERCEPTION）→ 意図的な編集（EDIT）** を、観客が自分の手でつないで、**一枚のオリジナル作品（EXPRESSION）へ到達する体験**にすることです。

**制作品質の合言葉**

> **FROM RULES TO WORLDS. FROM SEEING TO MAKING.**  
> **RULE → EMERGENCE → PERCEPTION → EDIT → EXPRESSION**  
> 見栄えだけの疑似科学にしない。単なる編集アプリにしない。既存ラボの価値を壊さない。

| `Emergence Engine/` | 局所ルールから秩序が自律的に生じる「生成作品」 | 今回は `04_flock.html` のBoidsモデルを中心に学ぶ |

未完成だった **L7 EXPRESSION** に、これらを結びつける独立した代表作を置く。

### 中心となる創作体験

1. **RULE:** ALIGN（同調）を入れる／切ると、同一初期条件の粒子群はどう変わる？
2. **EMERGENCE:** 観客は群れが形を作る過程を見つめ、自分でパラメータを動かす。
3. **PERCEPTION:** 何を主役にすると「群れ」が「視線を誘うグラフィック」へ変わる？
4. **EDIT:** どの粒子・線・余白・文字を残し、何を捨てる？
5. **EXPRESSION:** 同じ生成データから、複数の異なるポスターを作り保存する。

**本作の核は「自律的に生成した現象を、人間の編集意思で作品に変える瞬間」**。美しいだけのパーティクルアプリや、単なるBoidsパラメータデモとは異なる。

# 3. 最初の作品：L7 EXPRESSION COMPOSER v0.1

**作業ディレクトリ：** `expression-composer/` を新規作成。  
**画面の性格：** 編集ツールのUIというより、**鑑賞品質を持つ実験的なグラフィック装置**。  
**主題：** “A flock becomes a composition.”  
**初期モデル：** **Boids一種類に限定**。反応拡散・粘菌などの追加は v0.2以降。

## 3.1 体験の6シーン

| シーン | 観客の行為 | 起きる現象 | 画面に残す意味 |
|---|---|---|---|
| `00 / SEED` | BEGIN / 新seed | 散った点から運動が始まる | 世界は完成像を持たずに始まる |
| `01 / RULE` | SEPARATE・ALIGN・COHERE・NOISEを変える | 同じ群れのふるまいが変わる | 形の原因がルールにある |
| `02 / COMPARE` | `ALIGN ON / OFF` を同条件でA/B比較 | 同一seed・同一更新回数で秩序が異なる | 一つの法則の寄与が見える |
| `03 / FREEZE` | 気に入った瞬間に `TAKE STATE` | 実在した粒子配置・向きが固定される | 現象が創作用の素材になる |
| `04 / EDIT` | 残す点・強調・余白・文字・配色を選ぶ | 同じ粒子情報から異なる構図が出る | 意図的な省略が表現になる |
| `05 / OUTPUT` | PNG / JSONを書き出し、JSONを再読み込み | 作品を持ち帰り、同じ状態を再構成 | 過程が再現可能な成果になる |

ページ自体を6つの縦スクロールで分ける必要はない。**1画面の連続体験**とし、作業段階だけを移行する。`scroll-experience/` と役割を明確に分ける。

## 3.2 初回45〜90秒の「自然な導線」

- 開くと、いきなり乱雑なメニューではなく、**十分な余白と小さな粒子群**。`BEGIN / CHANGE A RULE` が控えめに見える。
- まず `ALIGN` のON/OFFを触ってみたくなる。切った瞬間に、なぜまとまりが変わるのかが絵として伝わる。
- `COMPARE` は同じseedとシミュレーション歩数を揃え、左がON・右がOFF（任意切替可）。
- `TAKE STATE` で現在の粒子配置を静止画素材化。ここで**動く世界が一枚の紙へ変わる**印象的なトランジションを入れる。
- EDITで余白・密度・強調・文字を選ぶとグラフィックが成立する。ラストは `EXPORT ARTWORK`。
- チュートリアルの長文は不要。必要な位置で1行だけ意味が伝わるテキストを出す。

# 4. 実装機能仕様（v0.1 必須）

## 4.1 RULE — 実際のBoids

**必須操作**

- `SEPARATE`（近づきすぎた粒子が離れる）
- `ALIGN`（周囲と方向をそろえる）＋**ON/OFF**（今回の主役）
- `COHERE`（群れの中心方向へ近づく）
- `NOISE`（ゆらぎ）
- `SEED`変更、`RESET`, `PLAY/PAUSE`, `STEP`（停止時の固定更新）
- プリセットは3個まで（例 `COHERE`, `DRIFT`, `FRACTURE`）。各プリセットは**実際のルール数値**に対応。

**科学・実装上の約束**

- 初期状態はseedつき疑似乱数から決定。更新は**固定時間刻み**で行い、描画フレーム時間と分離する。
- 比較時は同一seed・初期条件・粒子数・同一更新回数を用いる。唯一の比較要因だけ切り替える。
- `ALIGN OFF` でも他のルールは動いている。「OFFなら必ず全羽バラバラ」のような結果の保証・演出上の捏造はしない。
- エージェント数は端末性能に応じ適度に制限（v0.1目安300〜800）。**見た目優先で数を増やし続けない**。
- 先行する `04_flock.html` のモデルと異なる簡略化を採る場合、同一モデルと偽らず `docs/01_MODEL_NOTES.md` に差異を明記する。

## 4.2 COMPARE — 変化の因果を見せる

- 2つのパネルまたはワイプ比較。左右は**同一シミュレーション時刻**を共有する。左右の速度が違って比較不能になる状態を避ける。
- `ALIGN ON` vs `ALIGN OFF` が最初の固定比較。将来は比較するルールを選べるよう設計してよいが、UIに先行実装しない。
- 数値の裏付けとして `Φ (alignment / 平均進行方向の一致度)` を表示できると望ましい。定義と測定時点を表示し、`φ`（黄金比）と混同しない。
- 閾値を恣意的に設定して「生命誕生」などを科学的事実として表示しない。数値は**目で見える差への補助線**。
- A/B両方から `TAKE STATE` が選べる。比較後の素材は選択側の**実粒子データ**であること。

## 4.3 FREEZE — 生きたデータを素材へ

`TAKE STATE` を押した時点の各点の `id, x, y, vx, vy` 等を**変更不能なスナップショット**として確保。`seed / step / rules` を一緒に持つ。

- `FREEZE`後に元のルール値を変えても、**すでに確定した構図が勝手に変わらない**。
- 生成→編集の切替は `WORLD → PAPER` の意味を持つ、短く精度の高い転換演出とする。
- 不透明なランダム再配置、別データへのすり替え、画像だけのフェードでつないだ「ように見える」演出は禁止。
- `BACK TO RULES` で戻れる。編集中のスナップショットの扱い（保持／再取得）はUIに明示する。

## 4.4 EDIT — 「加工」ではなく「選択と省略」

**必須の編集ノブ（最小限）**

1. **KEEP** — 残す点の割合。元データから安定したID順・評価順に間引く。毎フレームランダムに点が入れ替わらない。
2. **FOCUS** — 注目位置（キャンバス上でクリック/タップ可）とその周辺の強調量。これは**作者が置く視線誘導**であり、人間の視線を自動測定していると誤認させない。
3. **SPACE** — グラフィックのスケール／余白。点が外にはみ出すのは意図した場合のみ。
4. **TRACE** — 粒子の速度ベクトルを短い線で残す長さ。スナップショットの実際の速度方向から描く。
5. **TYPE** — 見出し・短いサブコピーの入力／ON-OFF（最小限の文字組）。任意文字入力は描画・XSS・長文溢れに注意。
6. **LAYOUT PRESET** — `SILENCE / CURRENT / SIGNAL` の3種。同じスナップショットを素材に、編集意図だけを変える。

**3つの完成プリセット**

| Preset | 表現上の狙い | デフォルトの判断 |
|---|---|---|
| `SILENCE` | 省略によって存在感を増す | PAPER背景、残存点少、広い余白、文字控えめ |
| `CURRENT` | 流れと生命感を残す | NOIR背景、速度方向の痕跡、比較的多い点、強い方向性 |
| `SIGNAL` | 視線を一点へ集める | PAPER/INK＋意味のあるYELLOW、注目領域の強調と文字階層 |

**クリエイティブ上の重要条件:** `SILENCE` と `CURRENT` が**同じデータに由来することを観客が実感できる**。別々のランダムポスター生成器にしない。

## 4.5 OUTPUT — 完成品を持ち帰れる

- `EXPORT PNG`：最初は**1800×2400縦長**の1サイズを必須にする（余力があれば正方形追加）。Canvas上の拡大スクショではなく、**独立した出力サイズで構図を再レイアウト**。
- `SAVE STATE JSON`：schema version、seed、simulation step、rule values、スナップショット点配列（または厳密な再計算に必要な全情報）、選択プリセット、編集値、テキストを保存。
- `LOAD STATE JSON`：再読込で同じ粒子・構図に復帰する。入力ファイルはバージョン・サイズ・数値範囲を検証。未知キーを実行しない。画面外値やNaNを除外。
- `RESET` は明示的操作。作業中のパラメータを不用意に失わせない。
- 出力したPNGと画面内プレビューの**構図・余白・色・階層が意図通り一致**すること。画素単位の一致は出力サイズが違えば要求しない。
- v0.1では **SVG / MP4 / WebM / 音楽同期 / タイムライン / 3D / AI生成画像** は作らない。品質保証対象を絞る。

# 5. アートディレクション：Gen-EXの知的な美しさを継承

## 5.1 コンセプト

**LAB × EDITORIAL POSTER × LIVING SYSTEM**  
科学実験室の知性と、洗練されたグラフィックデザイン、偶発的な生命感の交点。**デモ画面なのに一枚の作品として見たくなる構図**を目指す。

ブランドの基本：

- `PAPER #F2F2EF`、`INK #0A0A0A`、`SIGNAL YELLOW #FFD400`。既存トークンを参照。
- 必要な場面のみEmergence系の `NOIR #070707`、`ICE #5AE9FF`。色数をやたら増やさない。
- 数字・ルール名は精密なモノスペース。大きな見出しは大胆だが、データ表示が主役を奪わない。
- 意味のないHUD飾り、四隅の記号、測定線、グリッドの乱用は禁止。**記号のすべてに意味を持たせる**。
- フォントは既存の参照方法を調べ、公開配布可能なものだけを使用。使えなければ代替フォントへフォールバック。
- 大画面：作品ステージが主役（おおむね70%）、操作は必要時に出る。スマホ：ステージ優先、操作UIを畳む。

## 5.2 動きと時間

- 初期の点群は**生命的に動く**一方、操作UIは**小気味よい制御感**。派手な擬似3D・過剰なスプリングは不要。
- FREEZEは「止まった」感覚を残し、そこから紙・レイアウトへ変容する。見せ場はここに置く。
- 強い転換と静寂の対比：**HOLD → BUILD → BREAK → REST**。何も起こらない余白は欠点ではない。
- 常時動かす必要のない画面は描画を止める。動かない状態に人工的な微振動を足さない。
- `prefers-reduced-motion` 対応。長いトランジションを短縮／省略し、機能は維持する。
- 操作は見た目より優先。スライダー操作中に視点が飛ばない。ドラッグ中に意図せず別モードへ変わらない。

## 5.3 3つの確認用キービジュアル

デザイン段階で、同一seed・同一スナップショットから：

- **Poster A / SILENCE**：白い大きな余白、左下に少数の点、強い静けさ。
- **Poster B / CURRENT**：黒地、流れが画面を横切る、見えない速度を感じる線。
- **Poster C / SIGNAL**：強い視線の中心、黄色い小さなシグナル、文字の階層。

上記は**方向性の例**。構図は実際に採取した生成データに従って調整する。テンプレートの見かけに合わせるためにデータを捏造しない。

# 6. 技術アーキテクチャ（提案。調査後に妥当な範囲で変更可）

新規フォルダに閉じた、静的HTML + CSS + JavaScriptを第一候補とする。フレームワークを導入するなら、依存や公開のメリットを必ず説明する。

```text
expression-composer/
  index.html
  styles.css
  README.md
  js/
    main.js                 # UIと画面遷移
    sim.js                  # seed付きBoidsと固定ステップ
    compare.js              # 同一初期条件のA/B実験
    snapshot.js             # immutable stateとJSON検証
    composition.js          # 同一粒子情報から編集構図を生成
    render.js               # PREVIEW / EXPORTで共用する描画
    export.js               # PNG / JSON / LOAD
  docs/
    00_AUDIT.md
    01_MODEL_NOTES.md
    02_CREATIVE_DECISIONS.md
    03_QA_REPORT.md
    04_NEXT_ROADMAP.md
  verification/
    screenshots/            # 確認可能な環境で収集
    contact-sheet.png       # 作れた場合
    test-results.json       # テスト実行で生成できた場合
```

注意：ファイル名と分割は固定契約ではない。大切なのは**粒子シミュレーション、比較、凍結、編集、描画、出力の責任を分けること**。

### 状態の一貫性

```text
Simulation(seed, fixedStep, rules)
       |
       +----> A/B Compare (same seed / same steps)
       |
       v
Immutable Snapshot(id, position, velocity, metadata)
       |
       +----> SILENCE composition
       +----> CURRENT composition
       +----> SIGNAL composition
       |
       v
Same Renderer -> Interactive Preview / High-res Export
       |
       v
PNG + reproducible JSON
```

- 変換途中で「新しいランダムな点群」を作らない。粒子`id`と元の物理状態の追跡が可能であること。
- スナップショットのデータは正規化座標かワールド座標を採用し、レイアウト変更時にも同じ点が追跡できる。
- `renderComposition(state, targetSize)` など、プレビューと書き出しで**描画ロジックをなるべく共通化**する。
- Seedとsimulation stepだけで完全再現できない外部入力があるなら、それもJSONに保存するか、スナップショット座標自体を保存する。
- ゲシュタルトの説明は認知的傾向として扱い、**実測した人間の視線や主観の証明**と混同しない。

# 8. QA：最低限の合格条件（実装後に必ず確認）

`docs/03_QA_REPORT.md` に **PASS / FAIL / NOT TESTED / 理由 / 証拠** の形で残す。

### 機能（必須）

- [ ] 新規HTMLをローカルHTTPで読み込める。致命的なJavaScript例外や404がない。
- [ ] RULEスライダーを操作すると**実際のシミュレーション挙動**が変化する。
- [ ] 同じseed・rule・stepで、同じ粒子状態を再現できる（許容誤差を定義）。
- [ ] ALIGN ON/OFFのA/Bが**同一seed・同一更新回数**で比較され、差を表示できる。
- [ ] A/Bから選んだ側の粒子状態が `TAKE STATE` に渡る。
- [ ] FREEZE後にシミュレーション操作を変えても、確定済み編集素材が勝手に変わらない。
- [ ] KEEP / FOCUS / SPACE / TRACE / TYPE / PRESET の操作が意味通り働く。
- [ ] 3ポスターが**同一スナップショットから生成**される。seedとparticle IDが追跡できる。
- [ ] PNGを1800×2400で保存でき、画面上の文字や要素が切れない。
- [ ] JSONを書き出し→再読み込みして、粒子位置・編集値・文字・構図を復元できる。
- [ ] 異常JSON、ファイル形式違い、大きすぎるファイルを安全に扱い、ユーザーに理由を表示する。
- [ ] 外部音源や有料APIなしで基本体験が成立する。

### 視覚・操作（必須）

- [ ] 1440×900、1280×800、390×844、844×390 で操作不能な重なり・はみ出しがない。
- [ ] マウス、タッチ相当操作、キーボードで主要機能にアクセスできる（実機未検証は区別）。
- [ ] `prefers-reduced-motion` で不要な演出が抑制されるが、機能は失われない。
- [ ] FREEZEの直前と直後に**元粒子の連続性**があり、無関係な図への差し替えになっていない。
- [ ] `SILENCE` は余白が成立、`CURRENT` は方向が伝わり、`SIGNAL` は主役の位置が分かる。
- [ ] PNGで色・書体・余白・主役がプレビューの意図と一致。比較用に実画像を並べて確認する。
- [ ] 常時点滅・過度なフラッシュ・唐突なレイアウトジャンプがない。

### 性能・技術（必須）

- [ ] シミュレーションの固定更新と描画速度を分離している。バックグラウンドから戻って無制限の追いつき計算をしない。
- [ ] PLAY中、PAUSE中、COMPARE中、EXPORT中のCPU/GPU負荷を確認。測れる環境ならFPSとp95フレーム時間を記録する。
- [ ] メモリ・描画負荷の主要因と適応的な粒子数／DPRの判断を記述する。
- [ ] 初期作品・既存LP・既存教材への回帰不具合がない（変更した範囲について）。
- [ ] headless/synthetic検証と**人間の手触りを確認した実機テスト**を混同しない。未実施ならNOT TESTED。

### 撮影すべき確認画像

1. SEEDの初期ステージ
2. ALIGN ON / ALIGN OFFの同条件比較
3. FREEZEの前後（元点の同一性が確認できる）
4. 同一データからのSILENCE / CURRENT / SIGNAL（並列コンタクトシート）
5. UI：desktop / mobile / short landscape
6. PNG実出力（最低1点）

**強い品質目標:** 適切なデスクトップ環境で60fpsを目指す。ただしGPU、粒子数、ブラウザに依存するため、**未測定の「常時60fps」を宣言しない**。

# 11. 採用しない方向（スコープ防衛）

- 「せっかくだから」エフェクト、シェーダー、3D、音、動画編集、AI生成、プリセット100種類を最初から追加しない。
- 無数のパラメータを見せるVJソフト風の画面にしない。音の必然性は別のGen-EX Realtime Expression Labで研究する。
- 既存のスクロールLPの世界観を取り込んで、もう一つの似たLPにしない。
- 数値ラベルだけで「知覚を計測した」と言わない。**観客が自分の目で違いを判断する**ことを中心にする。
- コンセプトに合わない機械的なスムーズ補間や、意味のない視差・回転を採用しない。
- 完成度の低い多数のラボを並べるより、**一つの素晴らしい創作体験を磨き切る**。

# 12. Codexへの最終作業命令

**この仕様に従い、PHASE 0〜3を実行してください。** 初回は**v0.1の縦断体験を最優先**し、既存資産を守りながら、必要な実装・修正・ブラウザ検証・レポートまで進めてください。クリエイティブな細部はあなたの裁量で最適化して構いませんが、**生成データの継承／同条件A-B比較／スナップショットの不変性／同じデータからの3ポスター／PNG・JSON再現**は崩さないこと。

優先順位は **①因果が本物である ②成果物のグラフィック品質 ③気持ちの良い操作と時間設計 ④追加機能**。

作業途中で既存コードに予想外の問題が見つかっても、全面改修に逃げず、新規作品に閉じた最小の解決を優先。根拠ある仕様変更は文書に記録。実装できなかった項目やブラウザ未確認項目は完成扱いにせず明記する。
